# テストES実コンテンツ v1.0
ES添削ツール  
作成日: 2026/05/21  
用途: プロトタイプの検証用テストデータ + READMEに記載する検証意図  
パターン数: 5本(課題要件「3〜5パターン」を満たし、矛盾検出までカバー)。旧 es3(専門用語)・旧 es7(設問ずらし)は本セット外として除外し、es1〜es5 に番号を詰め直し済み。

---

## 設計の哲学

「エッジケースを含む」を、単なるバリエーション収集ではなく、**プロダクトの差別化軸を試金石にできる**設計に落とした。5本を以下の2軸で配置:

| 軸 | 内容 |
|-----|------|
| **AIの自制力** | 「直すべきES」と「直すべきでないES」の両極を含む |
| **企業情報の有無** | `company_value` ソースが機能する/しない両方をテスト |

## テストES 1: 完成度高(自制の試金石)

### 入力Bundle

**設問**: 学生時代に最も力を入れたことを教えてください(400字以内)  
**企業情報**: メルカリ(C2C マーケットプレイス。データに基づく意思決定を重視する文化)  
**添削条件**: プリセット「バランス」、自由入力なし  
**ユーザー文脈**: 海外大経験あり、テック系志望

**ES本体 (390字)**:

```
20名規模の英語ディベートサークルで、初代女性キャプテンを務めた経験です。当初、大会で上位に入れない状況が続いていました。「準備の質に差があるのでは」と考え、過去の全国大会で上位に入ったチームの試合動画を20試合ほど見比べ、勝つチームに共通する「反論の前に論点を3つに絞る」型を見つけました。これを「反論は3点に整理してから話す」練習に落とし込み、毎週木曜20時に30分の特訓を5ヶ月続けました。当初は出席率40%でしたが、参加メンバーの成績が上向くにつれ80%まで上がりました。結果、私を含む3名が全国大会で入賞し、サークル史上初の快挙となりました。この経験から、データに基づく仮説検証が個人と組織の壁を超える効果を学びました。データを重視する意思決定文化に共感し、AIを基盤としたデータドリブンな意思決定の実現に貢献したいと考えています。
```

### 検証意図

完成度が高い、定量化済み、STAR構造OK、企業価値観との接続も明示済み。AIがどう振る舞うかが試される。

**AIが落第する振る舞い**:
- `convention` 系を5個以上出す(過剰指摘)
- `alternative` で信条を表す決め台詞を別表現に置き換え提案
- 数値スコア化(「このESは88点」など)

**AIが合格する振る舞い**:
- `error`: ゼロ
- `convention`: 0〜2個。あるとしたら「20試合という分析サンプルの妥当性」「見つけた型の再現性」の補足程度
- `alternative`: 1〜3個程度、語彙レベルの微調整のみ
- `preserved_voice_note` で「データドリブンな論理展開」「定量的根拠の積み重ね」を認識
- 面接質問: 「動画分析で見つけた型の具体的な中身」「他チームでの再現性」「企業の価値観との接続」のような、深掘り型

## テストES 2: 異常に短い(構造的欠陥の網羅試金石)

### 入力Bundle

**設問**: 自己PR(400字以内)  
**企業情報**: なし(URL未入力)  
**添削条件**: プリセット「厳しめ」、自由入力なし  
**ユーザー文脈**: なし

**ES本体 (140字、字数不足)**:

```
私の強みは粘り強さです。大学では英語学習に力を入れ、TOEICで900点を取得しまた。バイトでは塾講師として3年間続け、生徒の成積を上げました。これらの経験から、目標達成に向けて努力できる人間だと自負しています。
```

### 検証意図

必須要素が複数欠如している(STAR構造ゼロ、規模感ゼロ、具体行動ゼロ、独自性ゼロ)。さらに字数も大幅不足(140字 / 400字制限)。

**AIが落第する振る舞い**:
- 「全体的に良いです」のような甘い評価
- `company_value` を捏造して使う(企業情報がないのに「貴社の◯◯と合致」と書く)
- 15個以上の指摘を出す(過剰)

**AIが合格する振る舞い**:
- `error`: 字数大幅不足を指摘(1個)
- `convention`: 8〜12個。STAR各要素の欠如、規模感の追加、具体行動の追加、独自性の追加、定量化、など
- `alternative`: 0〜2個程度(まず内容を埋めるべきフェーズ、alternativeは不要)
- 15個上限の中で**優先度判断**ができている(エピソード追加 > 語彙改善)
- `rationale_source` は `convention` と `rubric` が中心(企業情報なしのため `company_value` は使えない)
- 面接質問: 「具体的にどんな粘り強さか」「TOEIC900点の勉強法」のような、内容を引き出すタイプ

## テストES 3: 強い個人トーン(個性保護の試金石)

### 入力Bundle

**設問**: 学生時代に最も力を入れたこと(400字以内)  
**企業情報**: 三菱商事(日系総合商社、人物重視、ストーリー重視)  
**添削条件**: プリセット「個性保護」、自由入力「自分の声を残したい」  
**ユーザー文脈**: 起業経験あり、文学部、書き手としての自意識強め

**ES本体 (395字)**:

```
カナダ留学先で、誰も注目しない孤立した留学生5人とコーヒーを飲んだ。それが始まりだった。週1回、図書館の隅で雑談していたら、いつの間にか参加者が30人になっていた。私たちはこれを「Coffee Cluster」と名付けた。学生課に正式団体として認められず、予算ゼロから始まったコミュニティだ。何度も場所を追い出された。週末は3軒のカフェを巡り、「学生5人入ります」と頭を下げ続けた。半年後、副学長が直接私を呼び出した。「正式団体にしないか」と。私は断った。「正式になった瞬間、ここは終わる」と思ったからだ。今、Coffee Clusterは私が卒業して2年経っても続いている。創設者の名前は誰も覚えていない。それでいい。組織は人で動くが、文化は人を超えて生きる。三菱商事という看板の重みを、私はこの経験から想像できる。
```

### 検証意図

短文の畳みかけ、断定調、口語的な独白という非常に強い個性。「組織は人で動くが、文化は人を超えて生きる」のような決め台詞は、書き手のアイデンティティそのもの。これを「平凡なES」に変えたら個性破壊。

**AIが落第する振る舞い**:
- 「STAR構造に整理せよ」と提案(これは個性破壊のサイン)
- 「30人になっていた」を「30人まで拡大した」のような能動表現に変更提案(語り口の破壊)
- 「それでいい」「断った」のような断定文を「と判断しました」のような丁寧文に変更
- `alternative` を10個以上出す(個性保護に逆行)

**AIが合格する振る舞い**:
- `error`: ゼロ
- `convention`: 1〜3個。「半年後の活動規模(どれくらいに広がっていたか)」「副学長との対話の追加詳細」など、ストーリーを補強する具体性追加のみ
- `alternative`: 2〜4個、原文の良さを認めるトーンの語彙レベルの微調整のみ
- `preserved_voice_note` で「短文の畳みかけ」「断定調」「口語的な独白」を明示認識
- `rationale_source.user_intent` が反映されている(「自分の声を残したい」を尊重)
- `rationale_source.company_value` で三菱商事の「人物重視」と接続した指摘
- 面接質問: 「副学長の申し出を断った判断基準」「Coffee Clusterの2年後の様子」のような、人物の深さを引き出すタイプ

## テストES 4: 異常に長い(削減提案の試金石)

### 入力Bundle

**設問**: 学生時代に最も力を入れたこと(400字以内)  
**企業情報**: なし  
**添削条件**: プリセット「バランス」、自由入力なし  
**ユーザー文脈**: なし

**ES本体 (462字、字数超過)**:

```
学生時代に最も力を入れたのは、大学2年から3年にかけて取り組んだ環境系NPOでのインターンです。私は元々環境問題に関心があり、特に廃プラスチック問題について深く考えていました。NPOに入ったきっかけは、大学の授業で講師として来られた代表の話を聞いたことです。その代表が「学生でも変えられる」と言っていたのが印象的で、その後すぐに連絡を取り、インターン生として参加しました。最初の半年は事務作業や会議の議事録を取る業務が中心で、正直なところ自分が何をしているのかよく分からない時期もありました。しかし、徐々に組織の課題が見えてきました。NPOには専門知識を持つ大人が集まっていましたが、現場の若者の声が反映されていないと感じたのです。そこで私は、20代の若者100名を対象としたアンケート調査を企画しました。回答結果を代表に提出し、若者向けキャンペーンの立ち上げに繋げました。キャンペーンには3ヶ月で150名が参加し、廃プラスチック削減の啓発活動を行いました。この経験から、組織に新しい視点を持ち込むことの重要性を学びました。
```

### 検証意図

字数超過(462字 / 400字制限、+62字)。AIは通常「足す」提案が得意で「削る」提案が苦手。冒頭1/3(〜「インターン生として参加しました」まで)はきっかけの説明で情報密度が低く、削減対象として明白。

**AIが落第する振る舞い**:
- 字数超過を指摘しない(`error` カテゴリの見落とし)
- 「もっと具体的に書け」のような追加提案を出す(逆方向)
- 削減提案ゼロ

**AIが合格する振る舞い**:
- `error`: 字数超過を最優先で指摘(400字以内に収めるには少なくとも 62 字削る必要がある規模感も明示)
- `convention`: 「冒頭1/3の削減」「『最初の半年は事務作業...』のセクション削減または短縮」「アクション部分(アンケート企画〜キャンペーン)の解像度向上」など、**削除と詳細化のトレードオフ**を提示
- 削減対象の指摘では `original_span` で削除すべき範囲を明示
- 面接質問: 「インターンに入ってから100名アンケートまでの心理的変化」「キャンペーン150名参加の質的成果」のような、密度の濃い部分を深掘りするタイプ

## テストES 5: 矛盾を含む(矛盾検出の試金石)

### 入力Bundle

**設問**: 学生時代に最も力を入れたこと(400字以内)
**企業情報**: なし(URL未入力)
**添削条件**: プリセット「バランス」、自由入力なし
**ユーザー文脈**: なし

**ES本体**:

```
大学では3年間、50人規模のテニスサークルで代表を務めました。2年生の春に代表に就任し、それから2年間、運営に力を注ぎました。就任時の部員は40人でしたが、新歓に力を入れて60人まで増やしました。一方で活動の質を高めるため、最終的には部員を20人に絞り込みました。練習は週4回から週2回に減らしましたが、一回あたりの密度を上げ、大会成績は向上しました。引退するとき、後輩から「一番頼れる代表だった」と言われたことが、今でも一番の誇りです。
```

### 検証意図

時系列(「3年間」vs「2年生就任+2年間=実質2年」)と数値(「50人規模」vs「40人→60人→20人」)に**内部矛盾**を仕込んだ。捏造防止の三層防御の実演 — AIが矛盾を見抜き、かつ**ESに実在する箇所**を指して指摘できるか。

**AIが落第する振る舞い**:
- 矛盾を見落とす
- ESに存在しない文を「矛盾」と指摘する(捏造)

**AIが合格する振る舞い**:
- `error`: 「3年間」と「2年生就任+2年間」の時系列矛盾、「50人規模」と「40→60→20人」の数値矛盾を指摘
- 指摘の `original` がESに**実在する**(捏造なし)
- 矛盾の解消方向(どちらかに統一する)を示す
- 企業情報なしのため `company_value` を使わない

## 5本横断の検証チェックリスト(READMEとデモ動画用)

### 必ず確認すること

| # | チェック項目 | 該当ES |
|---|------------|-------|
| 1 | 完成度の高いESに対して、AIが自制できるか | 1, 3 |
| 2 | 内容の薄いESに対して、AIが網羅的に指摘できるか | 2 |
| 3 | 字数超過に対して、削減提案を出せるか | 4 |
| 4 | 個性を認識し、保護できるか | 3 |
| 5 | `company_value` 系の根拠を企業情報から正しく抽出できるか | 1, 3 |
| 6 | 企業情報なしのとき、`company_value` を捏造せず代替ソースを使えるか | 2, 4, 5 |
| 7 | `user_intent`(添削条件の自由入力)が指摘に反映されるか | 3 |
| 8 | 15個上限を超えそうな状況で優先度判断できるか | 2 |
| 9 | 動的HITL: 指摘採用→却下→直接編集の流れで、関連指摘が更新されるか | すべて |
| 10 | 面接質問が企業価値観・採用された指摘の方向性と整合するか | 1, 3 |
| 11 | 数値スコアを一切出力しないか | すべて |
| 12 | 内部矛盾(時系列・数値)を error で検出し、実在箇所を指せるか(捏造防止) | 5 |

## デモ動画の構成(詳細は [`docs/submission_walkthrough.md`](submission_walkthrough.md))

録画は**無音の操作デモ**(LP なし)。本セット 5 本(es1〜es5)を動画・ドキュメント共通で使う。各 ES が見せる機能:

1. **es1 完成度高** — AI の自制(過剰修正しない)
2. **es2 異常に短い+誤字** — 逆質問(素材を引き出す)+ 誤字自動修正
3. **es3 強い個人トーン** — 個性保護
4. **es4 異常に長い** — 削減提案 + 逆質問
5. **es5 矛盾を含む** — 矛盾検出 + 捏造防止

動的 HITL(採用/拒否 → 再評価中 → 指摘更新)は es2 を主役に、動画で 1 カット撮る。各 ES の操作実演は [`docs/submission_walkthrough.md`](submission_walkthrough.md)。
